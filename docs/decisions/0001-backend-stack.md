# ADR 0001: стек і структура бекенду

Дата: 2026-10-11. Статус: прийнято.

## Контекст

Прототип бекенду зберігав суми як float, писав витрати в JSON-файл, не мав користувачів,
домогосподарств, валідації, міграцій і тестів.

## Рішення

- Монорепо на npm workspaces: `apps/api`, `apps/web`, `packages/shared`.
- Express 5, PostgreSQL через `pg`, Drizzle ORM; SQL-міграції генерує drizzle-kit у `apps/api/drizzle`.
- Валідація — zod-схеми з `packages/shared`. Пакет підключається як TypeScript-вихідники, без збірки.
- Тести — Vitest; API перевіряється через Supertest на окремій базі PostgreSQL (`TEST_DATABASE_URL`).
- Гроші — цілі мінімальні одиниці в `BIGINT`, у коді `number` у межах безпечного цілого.
- Витрати й доходи об'єднано в одну сутність Transaction; стару таблицю `expenses` видалено
  першою міграцією без перенесення даних.

## Наслідки й відкладене

- Авторизація — окремий етап; рішення описано в ADR 0002, dev-заглушку видалено.
- Користувач поки може мати одне активне домогосподарство: береться найраніше членство.
- Баланси рахунків, Budget, Debt, Goal і аналітика ще не реалізовані.
