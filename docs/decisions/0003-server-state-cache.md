# ADR 0003: кеш даних сервера на фронтенді

Дата: 2026-10-18. Статус: прийнято.

## Контекст

Кожен перехід між сторінками повторно запитував дані, які не змінювались: повторний обхід дев'яти
сторінок меню давав 23 GET-запити. React Query вже був у проєкті, але з `staleTime: 0` вважав будь-які
дані застарілими одразу після отримання. Мутації самі перелічували, які ключі скинути, і ці списки вже
розходились із реальними залежностями (видалення рахунку й категорії, зміни цілей, боргів і прибутків
не оновлювали головну).

## Рішення

- Окремого стор-менеджера (Redux, Zustand) немає: дані сервера живуть лише в кеші React Query.
  Другий кеш тих самих даних довелося б синхронізувати вручну.
- Налаштування — в `apps/web/src/app/queryClient.ts`: дані свіжі 5 хвилин (`staleTime`), кеш сторінки
  живе 30 хвилин після того, як її покинули (`gcTime`). `refetchOnWindowFocus` лишається увімкненим і
  підтягує зміни з інших пристроїв, коли дані старші за 5 хвилин.
- Одне правило актуальності: будь-яка успішна мутація робить застарілими всі запити
  (`MutationCache.onSuccess` → `invalidateQueries()`). Одразу перечитуються лише запити відкритої
  сторінки, решта — коли сторінку відкриють. Мутація лишається pending, доки відкрита сторінка не
  оновиться, тож діалоги закриваються вже зі свіжими даними.
- Запити, яких це правило не стосується (сесія `me`, налаштування входу), мають
  `staleTime: 'static'`: їх не перечитують ні час, ні мутації, лише явний `refetch()`.
- Під час розробки доступні React Query Devtools; у production-збірку вони не потрапляють.

## Як із цим працювати

- Нова мутація — це просто `useMutation({ mutationFn })`, без `onSuccess` зі скиданням ключів.
- Новий запит, який не повинен перечитуватися після мутацій, отримує `staleTime: 'static'`.
- `e2e/cache.spec.ts` перевіряє обидва боки: повторна навігація не робить запитів, а зміна на одній
  сторінці видна на іншій, уже відкритій раніше.

## Наслідки й відкладене

- Після мутації можуть перечитатися зайві запити відкритої сторінки (наприклад, категорії після
  збереження транзакції). За поточної частоти змін це дешевше, ніж підтримувати карту залежностей.
- Зміни, зроблені з іншого пристрою, з'являються не раніше ніж дані застаріють (до 5 хвилин) і вкладка
  отримає фокус або сторінку відкриють знову. Push-оновлень із сервера немає.
- Prefetch сторінок при наведенні на пункт меню не зроблено: перший відкрив сторінки йде в мережу.
