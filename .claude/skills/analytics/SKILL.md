# Аналітика

Перед роботою прочитай CLAUDE.md (правила щодо грошей, дат і доступу до даних), docs/domain.md
та скіли `monthly-budget`, `incomes` і `debts`: аналітика лише читає їхні дані.

## 1. Що робить фіча

Екран «Аналітика» показує, куди йдуть гроші й як змінюється фінансовий стан домогосподарства.
Нічого не зберігає: усе рахується з транзакцій, бюджетів, доходів і боргів.

Чотири блоки:
1. **Витрати за категоріями** — розподіл витрат обраного місяця: сума, частка,
   зміна відносно попереднього місяця.
2. **Доходи й витрати по місяцях** — динаміка за 6 або 12 місяців: дохід, витрати, різниця,
   норма заощаджень.
3. **Перевитрати й прогноз місяця** — категорії з перевищеним лімітом бюджету і прогноз витрат
   до кінця поточного місяця.
4. **Чисті активи й боргове навантаження** — чисті активи на кінець кожного місяця і частка
   доходу, що йде на борги.

Період: перемикач місяця (у майбутнє не гортається) і перемикач довжини динаміки «6 / 12 місяців».
Динаміка закінчується обраним місяцем.

## 2. Що вважається витратою і доходом

Ті самі правила, що й у бюджеті (див. `monthly-budget`, розділ 2, і `debts`, розділ 5):

| Транзакція | Витрата | Дохід |
|---|---|---|
| `expense` (зокрема покупки, відсотки й комісії з кредитки) | так | — |
| `debt_payment` (платіж по позиці, категорія «Погашення боргів») | так | — |
| `income` (зокрема повернення коштів на кредитку) | — | так |
| `transfer` (зокрема погашення кредитки) | ні | ні |
| `balance_adjustment` | ні | ні |

- Транзакція належить до місяця за `occurredAt` у таймзоні household; період — півінтервал.
- Враховуються лише транзакції у валюті `UAH`. Суми різних валют не складаються.
- Повернення коштів на кредитку рахується доходом: воно записується звичайним `income`.

## 3. Розрахунки (чисті функції в packages/shared/analytics)

Усі суми — цілі числа в копійках. Частки й норми — відношення (число), не суми.

### Витрати за категоріями
Для кожної категорії, що має витрати в обраному або попередньому місяці:
```
spent         = витрати категорії в обраному місяці
previousSpent = витрати категорії в попередньому місяці
change        = spent - previousSpent
share         = totalSpent > 0 ? spent / totalSpent : 0
```
Витрати без категорії — окремий рядок «Без категорії». Сортування — за `spent` за спаданням.
Підсумок: `totalSpent`, `previousTotalSpent`, `change`.

### Місяць у динаміці
```
income      = сума доходів місяця
expenses    = сума витрат місяця
net         = income - expenses
savingsRate = income > 0 ? net / income : null
```
Місяць без транзакцій дає нулі й `savingsRate = null`.

### Прогноз місяця (лише поточний місяць)
`forecastSpending(spent, daysElapsed, daysInMonth)`:
```
projected = round(spent * daysInMonth / daysElapsed)
```
- `daysElapsed` — кількість днів від першого числа до сьогодні включно (у таймзоні household).
- Рахується для всіх витрат місяця і окремо для кожної категорії з лімітом бюджету:
  `projectedOverBy = max(0, projected - planned)`.
- Для минулих місяців прогнозу немає (`null`): там уже є факт.
- Це лінійна екстраполяція темпу, а не обіцянка; UI показує це підказкою.

### Перевитрати
Беруться з бюджету обраного місяця, без власної логіки:
- рядки бюджету зі статусом `over` → `overBy = spent - planned`;
- незаплановані витрати → `planned = 0`, `overBy = spent`.
Якщо бюджету на місяць немає — `budget = null`, UI пропонує створити бюджет.

### Чисті активи
```
netWorth = сума балансів усіх рахунків у UAH − залишки позик і розстрочок
```
- Борг кредитної картки вже є відʼємним балансом її рахунку, тому окремо не віднімається.
- Значення береться на кінець кожного місяця динаміки.
- Залишок позики на кінець місяця: `initialAmount + нарахування − тіло платежів + звірки`
  з рухів до кінця місяця, не менше 0; до `startDate` позики її боргу немає.
- Перекази між рахунками на суму балансів не впливають.

### Боргове навантаження
```
debtPayments = платежі по позиках (debt_payment) + перекази на рахунки кредиток за місяць
debtLoad     = income > 0 ? debtPayments / income : null
```
Планове навантаження обраного місяця:
```
plannedDebtLoad = plannedIncome > 0 ? totalMonthlyPayments / plannedIncome : null
```
де `totalMonthlyPayments` — з огляду боргів, `plannedIncome` — `plannedTotal` доходів місяця.

## 4. API

```
GET /analytics/month?month=2026-10
GET /analytics/trend?month=2026-10&months=6     // months: 6 | 12, за замовчуванням 6
```
Обидва endpoint-и лише читають. `month` за замовчуванням — поточний; майбутній місяць → 400.

Приклад `GET /analytics/month?month=2026-10`:
```json
{
  "month": "2026-10", "currency": "UAH", "today": "2026-10-12", "isCurrentMonth": true,
  "totalSpent": 3180000, "previousTotalSpent": 2900000, "change": 280000,
  "categories": [
    { "categoryId": "...", "categoryName": "Продукти", "spent": 1350000, "share": 0.4245,
      "previousSpent": 1200000, "change": 150000 }
  ],
  "budget": {
    "overspent": [
      { "categoryId": "...", "categoryName": "Продукти", "planned": 1200000, "spent": 1350000, "overBy": 150000 }
    ]
  },
  "forecast": {
    "daysElapsed": 12, "daysInMonth": 31, "spent": 3180000, "projected": 8215000,
    "plannedExpenseTotal": 5200000,
    "categories": [
      { "categoryId": "...", "categoryName": "Продукти", "planned": 1200000, "spent": 1350000,
        "projected": 3487500, "projectedOverBy": 2287500 }
    ]
  }
}
```
`budget` — `null`, якщо бюджету на місяць немає; `forecast` — `null` для минулих місяців.
`forecast.plannedExpenseTotal` і `forecast.categories` порожні (`null` і `[]`), якщо бюджету немає.

Приклад `GET /analytics/trend?month=2026-10&months=6`:
```json
{
  "month": "2026-10", "months": 6, "currency": "UAH",
  "points": [
    { "month": "2026-05", "income": 6000000, "expenses": 5100000, "net": 900000, "savingsRate": 0.15,
      "netWorth": 12400000, "debtPayments": 390000, "debtLoad": 0.065 }
  ],
  "plannedDebtLoad": { "monthlyPayments": 390000, "plannedIncome": 6000000, "ratio": 0.065 }
}
```

Правила:
- Кожен запит фільтрується за household поточного користувача.
- Агрегація по місяцях — згрупованими SQL-запитами, а не циклом запитів по місяцях.
- Дані бюджету, доходів і боргів беруться через їхні сервіси, без дублювання їхнього SQL.

## 5. База даних

Міграцій немає. Використовується наявний індекс
`transactions (household_id, type, occurred_at, category_id)`.

## 6. UI (apps/web/src/features/analytics)

- Графіки — Recharts через компонент shadcn `chart`; кольори з токенів теми з підтримкою темної теми.
- Поруч із кожним графіком є таблиця тих самих чисел (доступність і точні значення).
- Колір ніколи не є єдиним індикатором: перевитрата — іконка ⚠ і текст «Перевищено на X ₴»,
  відʼємна різниця місяця — знак «−» і текст.
- Блоки:
  - «Витрати за категоріями»: горизонтальні стовпчики + таблиця (сума, частка, зміна);
  - «Доходи й витрати»: стовпчики доходу й витрат по місяцях + таблиця з різницею й нормою заощаджень;
  - «Перевитрати й прогноз»: список перевитрат; для поточного місяця — прогноз усіх витрат
    проти суми лімітів і категорії, які за прогнозом перевищать ліміт; підказка про лінійний темп;
  - «Чисті активи й борги»: лінія чистих активів по місяцях, боргове навантаження місяців
    і планове навантаження обраного місяця.
- Порожні стани: місяць без витрат, немає бюджету, немає боргів.
- Запити аналітики інвалідуються після будь-якої зміни транзакцій, бюджету, доходів і боргів.

## 7. Тести (обовʼязкові)

Unit:
- категорії: частки, зміна, категорія лише в попередньому місяці, без категорії, порожній місяць
- `savingsRate`: дохід 0 → null; витрати більші за дохід → відʼємна
- `forecastSpending`: перший день місяця, останній день (projected = spent), округлення
- чисті активи: позика до `startDate` не враховується; залишок позики не менший за 0
- `debtLoad`: дохід 0 → null

API (Supertest):
- перекази й `balance_adjustment` не входять ні у витрати, ні в доходи; `debt_payment` — витрата
- транзакція 31-го о 23:30 за Києвом рахується в цьому місяці
- чужі дані не потрапляють в аналітику
- місяць без бюджету → `budget: null`; минулий місяць → `forecast: null`; майбутній місяць → 400
- перевитрати збігаються з рядками `over` і незапланованими витратами бюджету
- динаміка містить рівно `months` точок, включно з місяцями без даних
- чисті активи: переказ між рахунками їх не змінює; платіж по позиці не змінює
  (рахунок і борг зменшуються однаково, якщо весь платіж — тіло); покупка з кредитки зменшує
- боргове навантаження враховує платіж по позиці й переказ на кредитку

E2E (Playwright): видатки у двох категоріях і дохід → на екрані аналітики видно суми категорій,
дохід, витрати й різницю місяця.

## 8. Порядок реалізації

1. Чисті функції + unit-тести.
2. API місяця + API-тести.
3. API динаміки + API-тести.
4. Підключення `recharts` і shadcn `chart`.
5. UI: категорії → динаміка → перевитрати й прогноз → чисті активи й борги.
6. E2E, оновлення docs/api.md і docs/domain.md.

Кожен крок — окремий коміт.

## 9. Поза межами цієї фічі
- тексти порад і стратегії погашення боргів (avalanche/snowball) — окремий скіл;
- довільний діапазон дат, порівняння років, експорт;
- мультивалютність і конвертація;
- цілі накопичення;
- відокремлення повернень на кредитку від доходів.
