# Головна

Перед роботою прочитай CLAUDE.md і скіли `monthly-budget`, `incomes`, `debts`, `goals`, `analytics`:
головна лише збирає їхні дані.

## 1. Що робить фіча

Головна відповідає на три питання за один погляд: скільки в мене грошей, як іде цей місяць
і що потребує уваги сьогодні. Нових розрахунків вона не вводить: усі числа й статуси вже порахували
інші розділи, а кожен блок веде на свою сторінку.

Показується лише поточний місяць (у таймзоні household), без перемикача: історія є в аналітиці.

Блоки:
1. **Шапка** — привітання, поточний місяць, швидкі дії «+ Видаток», «+ Дохід», «Переказ»
   (ті самі модалки, що й у розділах).
2. **Гроші зараз** — чисті активи, сума на рахунках, загальний борг; активні рахунки з балансами.
3. **Цей місяць** — дохід, витрати, різниця; «витрачено з суми лімітів» і прогноз на кінець місяця.
4. **Потребує уваги** — список подій, найважливіше згори.
5. **Найближчі платежі й надходження** — до кінця місяця, за датою.
6. **Цілі** — до трьох активних цілей із прогресом.
7. **Останні операції** — пʼять останніх витрат, доходів і платежів по боргах.

Новий користувач без рахунків бачить замість блоків кроки:
створити рахунок → додати дохід чи видаток → скласти бюджет.

## 2. Звідки беруться дані

| Дані | Джерело |
|---|---|
| баланси рахунків | рахунки (`balance`) |
| загальний борг, статуси платежів | огляд боргів (`debts`) |
| дохід місяця, очікувані надходження | доходи місяця (`incomes`) |
| витрати, перевитрати, прогноз, сума лімітів | аналітика місяця (`analytics`) |
| цілі | список цілей (`goals`) |
| останні операції | транзакції |

Сервіс головної викликає сервіси цих розділів і не дублює їхній SQL та правила.

## 3. Розрахунки (чисті функції в packages/shared/dashboard)

### Гроші зараз
```
accountsTotal = сума балансів усіх рахунків у UAH
debtTotal     = totalBalance з огляду боргів (кредитки, позики, розстрочки)
netWorth      = accountsTotal − залишки активних позик і розстрочок
```
Борг кредитки вже є відʼємним балансом її рахунку, тому з чистих активів окремо не віднімається —
та сама формула, що в `analytics`. У списку рахунків — лише неархівні, у всіх валютах.

### Цей місяць
```
income   = receivedTotal доходів місяця
expenses = totalSpent аналітики місяця
net      = income − expenses
projected, plannedExpenseTotal — з прогнозу аналітики місяця
```
Без бюджету `plannedExpenseTotal = null`, UI пропонує створити бюджет.

### Потребує уваги `buildAttention`
Елементи беруться з готових статусів, порядок видів фіксований:

| № | `kind` | Умова | Сума | Дата |
|---|---|---|---|---|
| 1 | `debt_overdue` | активний борг, статус платежу `overdue` | `required − paid` | `dueDate` |
| 2 | `income_overdue` | надходження зі статусом `overdue` | `plannedAmount − actualAmount` | `plannedDate` |
| 3 | `budget_over` | перевитрата з аналітики місяця | `overBy` | — |
| 4 | `goal_overdue` | активна ціль зі станом `overdue` | — | `targetDate` |
| 5 | `debt_due_soon` | активний борг, статус платежу `due_soon` | `required − paid` | `dueDate` |
| 6 | `goal_behind` | активна ціль зі станом `behind` | `requiredMonthly` | `targetDate` |

У межах одного виду: з датою — раніша дата першою, без дати — більша сума першою.
Порожній список → UI показує «Усе під контролем» з іконкою ✓.

### Найближчі події `buildUpcoming`
До кінця поточного місяця, з датою не раніше за сьогодні:
- платежі по активних боргах зі статусом `pending`, `due_soon` або `partial` → `required − paid`, `dueDate`;
- надходження зі статусом `pending` або `partial` → `plannedAmount − actualAmount`, `plannedDate`.
Сортування — за датою, потім за назвою. Прострочене сюди не входить: воно в «Потребує уваги».

## 4. API

```
GET /dashboard     → зведення поточного місяця; лише читання
```
Приклад:
```json
{
  "month": "2026-10", "today": "2026-10-12", "currency": "UAH",
  "setup": { "hasAccounts": true, "hasTransactions": true, "hasBudget": true },
  "money": { "netWorth": 12400000, "accountsTotal": 13400000, "debtTotal": 3340000,
             "accounts": [{ "id": "...", "name": "Картка", "type": "card", "currency": "UAH", "balance": 4200000 }] },
  "monthSummary": { "income": 6000000, "expenses": 3180000, "net": 2820000,
                    "plannedExpenseTotal": 5200000, "projected": 8215000,
                    "daysElapsed": 12, "daysInMonth": 31 },
  "attention": [
    { "kind": "debt_overdue", "id": "...", "name": "Позика", "amount": 100000, "date": "2026-10-10" },
    { "kind": "budget_over", "id": "...", "name": "Продукти", "amount": 150000, "date": null }
  ],
  "upcoming": [
    { "kind": "debt_payment", "id": "...", "name": "Кредитка", "amount": 120000, "date": "2026-10-25" },
    { "kind": "income", "id": "...", "name": "Аванс", "amount": 1500000, "date": "2026-10-15" }
  ],
  "goals": [],
  "recent": [
    { "id": "...", "type": "expense", "description": "Супермаркет", "categoryName": "Продукти",
      "accountName": "Картка", "amountMinor": 128450, "currency": "UAH", "occurredAt": "2026-10-11T10:30:00.000Z" }
  ]
}
```
- `attention[].id` — id боргу, надходження чи цілі; для `budget_over` — id категорії або `null`.
- `goals` — об'єкти цілей, як у `GET /goals`, не більше трьох активних.
- `recent` — не більше пʼяти; перекази й службові зміни балансу не показуються.

Правила: запит фільтрується за household поточного користувача; жодних записів не створює,
крім лінивої генерації надходжень, яку робить сервіс доходів.

## 5. UI (apps/web/src/features/dashboard)

- Кожен блок має заголовок-посилання на свій розділ.
- «Потребує уваги»: іконка й текст для кожного виду («Прострочено платіж», «Не надійшов дохід»,
  «Перевищено ліміт», «Строк цілі минув», «Платіж скоро», «Ціль відстає»); високий пріоритет
  (види 1–4) — стиль `over`, решта — `partial`. Колір ніколи не є єдиним індикатором.
- «Цей місяць»: смуга «витрачено з суми лімітів»; якщо прогноз перевищує суму лімітів —
  попередження з іконкою.
- Швидкі дії відкривають спільні модалки видатку, доходу й переказу; після збереження
  запит головної інвалідується. Під час повернення на головну дані перечитуються.
- Порожній стан із трьома кроками, кожен — посилання; виконаний крок позначений ✓.

## 6. Тести (обовʼязкові)

Unit:
- `buildAttention`: кожен вид; порядок видів; сортування в межах виду; закриті борги й архівні цілі
  не потрапляють; порожній список
- `buildUpcoming`: лише майбутні дати до кінця місяця; сплачене не потрапляє; часткове — із залишком;
  сортування за датою й назвою

API (Supertest):
- новий користувач: `setup` з `false`, нулі, порожні списки
- гроші: чисті активи = рахунки − позики; кредитка не віднімається двічі; архівний рахунок не в списку
- місяць: дохід і витрати збігаються з доходами й аналітикою; без бюджету `plannedExpenseTotal = null`
- кожен вид попередження зʼявляється за своєї умови
- найближчі події: платіж по боргу й очікуване надходження
- останні операції: без переказів, не більше пʼяти, найновіші першими
- чужі дані не потрапляють; без токена → 401

E2E (Playwright): новий користувач бачить кроки → створює рахунок → додає видаток із головної →
блок «Цей місяць» показує витрати; після перевищення ліміту зʼявляється «Перевищено ліміт».

## 7. Порядок реалізації

1. Чисті функції + unit-тести.
2. `GET /dashboard` + API-тести.
3. UI: шапка зі швидкими діями → гроші → місяць → увага → найближчі події → цілі → останні операції.
4. E2E, оновлення docs/api.md і docs/domain.md.

Кожен крок — окремий коміт.
